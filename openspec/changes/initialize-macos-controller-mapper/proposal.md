## Why

当前工程仅包含默认的 SwiftUI 示例界面，还没有作为 macOS 游戏手柄映射工具所需的常驻入口、设备状态展示和权限准备流程。先建立可运行、可观察手柄输入的应用骨架，可以验证 GameController 接入与核心交互，并为后续“手柄按键映射为键盘按键”能力打下稳定基础。

## What Changes

- 新增菜单栏常驻图标；用户点击后可打开或重新聚焦唯一的应用主窗口，关闭窗口后应用继续运行。
- 将主界面组织为上下两部分：顶部横向展示当前已连接的游戏手柄，底部展示当前选中设备可用的按键列表。
- 监听游戏手柄的连接、断开和按键按下/松开事件；按键处于按下状态时，对应列表项实时高亮，松开后恢复。
- 新增首次启动权限引导，说明输入监控与辅助功能权限的用途，由用户逐项触发系统授权，并显示实时授权状态；允许暂时跳过且可再次打开引导。
- 为无设备、设备断开、选中设备变化和权限未授予等状态定义明确的界面行为。
- 增加关键状态模型和首次启动流程的自动化测试；本阶段不创建或执行实际的键盘映射。

## Capabilities

### New Capabilities

- `menu-bar-app-shell`: 定义菜单栏入口、单一主窗口的打开/聚焦行为，以及主窗口的上下分区布局。
- `controller-input-visualization`: 定义已连接设备的发现与选择、按键列表展示，以及实时按下高亮行为。
- `first-run-permissions`: 定义首次启动权限引导、用户触发的系统授权、状态刷新、跳过与再次打开流程。

### Modified Capabilities

无。

## Impact

- 影响 `JoyCodingApp.swift`、`ContentView.swift` 及新增的应用状态、手柄服务、权限服务和对应 SwiftUI 视图。
- 使用系统 `GameController`、`ApplicationServices` 与 `IOKit.hid` API，不引入第三方运行时依赖。
- Xcode 工程需包含必要的隐私用途说明和测试目标配置；应用继续以现有 macOS 部署目标为准。
- 参考 `/Users/shiye/work/xbox-controller-mapper` 的事件绑定与权限分步引导思路，但仅实现本阶段所需的最小能力，不复制其映射、原始 HID、许可或更新体系。
